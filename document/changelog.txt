ChangeLog

2026/10/19 Phase 9.1.0 (Core 4.1.0)
 * add "lambda": defines an anonymous function and returns its name
   (System.Lambda.<n>, never the same as a defined function). The body is
   written like that of "function", and the returned name is used as a
   command name ($(${f} args)) or passed to another function. It is not a
   closure: the local entries (@arg etc.) of the place where it was defined
   are not carried. Remove it with "rmfunc"
 * updated uka_regexp (build/src/uka_regexp):
   - (*UCP) at the head of a pattern makes \d \w \s \b and the POSIX classes
     use the Unicode properties (the default is still ASCII only)
   - where wchar_t is 16 bit (Windows), a surrogate pair is one character in
     a pattern (. and [^a] match a whole emoji, and a match never starts or
     ends in the middle of a pair). The positions given to KIS are still
     counted in wchar_t
   - a{,m} is accepted as a{0,m}, \K in a lookaround is rejected, and
     catastrophic backtracking now ends in polynomial time
   - fixed the output string aliasing the subject or the template in Replace(),
     and the capacity overflow of the internal buffers (it now throws
     ERR_MEMORY); a start offset inside a surrogate pair is moved to the next
     character boundary
 * removed the notes of the unimplemented "expr" and "test" from the manual,
   and the finished or abandoned items (boost regex, rexpr, SAORI/2.0, i18n
   patch) from the plan in README.md

2026/10/18 Phase 9.0.0 beta4 (Core 4.0.0)
 * add the regular expression commands "regex_match", "regex_find",
   "regex_findall", "regex_count", "regex_replace", "regex_replace_first",
   "regex_erase", "regex_erase_first", "regex_split" and "regex_escape",
   on the engine uka_regexp (build/src/uka_regexp, a git submodule; clone
   with --recursive or run "git submodule update --init"). The syntax is
   close to PCRE2; \d \w \s \b match ASCII only. The matches, the groups and
   the pieces are stored to the entry given as an argument
 * a subroutine call in a pattern, (?&name) or \g<name>, whose name the
   pattern does not define is replaced with the expansion of the entry
   ${name}. A pattern with parentheses must be quoted ("...") in the
   dictionary and the script
 * makedepend.rb resolves #include "foo.h" of the same folder (needed by
   uka_regexp) and is converted from CP932 to EUC-JP

2026/10/18 Phase 9.0.0 beta3 (Core 4.0.0)
 * fixed: the module names of SAORI over DirectSSTP were lowercased with
   towlower(), which depends on the LC_CTYPE of the host (with tr_TR, "I"
   became U+0131 and "INTERNAL_..." was not recognized). Only ASCII letters
   are lowercased now
 * fixed the misuse of the STL:
   - the destructor of the unique SAORI module factory used an iterator
     after erase()
   - the result of find() was kept in "unsigned int" and compared with
     npos. On 64-bit POSIX the comparison never became true, so "gsub"
     (when no more match is left) threw an exception, "tr" read out of
     bounds, and "isexist" did not append the separator. "split", the
     "match" family and the status line of SAORI are changed to
     size_type too (no change of behavior). On 32-bit Windows nothing
     changes
   - the length given to "substr" could overflow
   - decoding a broken Base64 text with more "=" than the decoded length
     threw an exception
   - internal only (not reachable from KIS so far): TEntry::Pop on an entry
     emptied by Clear() called back() on an empty vector, and
     TEntry::Replace accepted the index just past the last word

2026/10/18 Phase 9.0.0 beta2 (Core 4.0.0)
 * add "getproperty", "setproperty" and "executesstp"/"executesstpx":
   property system and SSTP EXECUTE commands sent to the baseware (SSP, ninix)
   by Direct SSTP. The window of the baseware is taken from "NOTIFY hwnd".
   The response code is stored to System.SSTP.ResponseCode and the additional
   data to System.SSTP.Data ("executesstpx" also stores it to the given entry)
 * SAORI over DirectSSTP: the modules built in the baseware (internal_*, and
   the compatible ones such as houchi/httpc/string) can be called with
   "callsaori" like a SAORI without a DLL. "saoriregist" a name without a DLL
   file, or call an unregistered "internal_*" name (checked with ListModules of
   internal_system). A DLL file, if it exists, is loaded as before
 * the commands above are refused for requests whose SecurityLevel is not local
 * Linux: link with -lrt -lpthread (FMO of ninix)
 * fixed: System.Sender.Path was never set, so "callsaori" always sent
   "SecurityLevel: Local" to SAORI. It is now set for every request (local /
   external / unknown) and used as the SecurityLevel of the SAORI request

2026/10/18 Phase 9.0.0 beta1 (Core 4.0.0)
 * changed the internal strings to wchar_t (UTF-16 on Windows, UTF-32 on
   POSIX). Characters outside the BMP (e.g. emoji) count as 2 characters
   on Windows
 * fixed the file/folder name problem with Shift_JIS characters whose second
   byte is 0x5C etc. and with IBM/NEC extension characters (isdir, isexist,
   readdir...)
 * changed string comparison ("compare", "<" ">" in expression, the order of
   entry enumeration) to Unicode code point order instead of Shift_JIS byte
   order (no change for ASCII)
 * dictionary files: auto-detect UTF-8 (BOM, or valid UTF-8 as a whole) and
   Shift_JIS (CP932). Encrypted lines (!KAWA0000/!KAWA0001) are read as UTF-8
   when the file has a BOM, otherwise as Shift_JIS
 * "save"/"savecrypt" now write UTF-8 with BOM (a dictionary saved by
   "save" or "savecrypt" cannot be read correctly by 8.2.9 or earlier: the
   BOM breaks the first line and Japanese text is read as Shift_JIS)
 * "textload" detects UTF-8/Shift_JIS automatically. "textsave"/"textappend"
   write UTF-8 without BOM ("textappend" appends UTF-8 even to a Shift_JIS file)
 * kawari_encode/kawari_encode2 add a BOM to the output when the input is
   UTF-8. kawari_decode2 adds a BOM when the input has a BOM
 * SHIORI: interpret the request by its Charset header and answer in the same
   charset (Shift_JIS when absent or unknown). Every response has a Charset
   header; System.Response.Charset (Shift_JIS/UTF-8) can select it
 * SHIORI: export "loadu" (load with a UTF-8 path)
 * SAORI: start with UTF-8, follow the Charset of the GET Version response
   (Shift_JIS when absent), interpret responses by their Charset, and call
   "loadu" of the SAORI DLL if it is exported
 * "rccharset" accepts UTF-8 as well as Shift_JIS (Japanese messages)
 * "logfile" writes UTF-8 without BOM. kosui console I/O uses the ANSI code
   page (UTF-8 on POSIX)
 * "chr", "toupper/tolower" and "escape" keep their behavior (ASCII only /
   Shift_JIS code interpretation)
 * Win32 API: W versions (UNICODE), WINVER=0x0500 (Windows 2000)
 * non-Windows builds use iconv for charset conversion (-liconv on
   FreeBSD/darwin)
